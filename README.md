# InventorGostSpec

Аддин для Autodesk Inventor 2025, формирующий спецификацию по ГОСТ 2.106-2019.

Возможности:

- назначение компонентам категорий (разделов спецификации) через iProperties, в том числе автоматически для стандартных изделий из Content Center;
- формирование спецификации по первому уровню сборки со строгой сортировкой по ГОСТ;
- ручное редактирование порядка, разделов, примечаний и любых колонок;
- обновление только по команде пользователя, с сохранением ручных правок;
- резерв номеров позиций между разделами;
- запись позиций в BOM Inventor;
- экспорт в Excel для ручной правки и вывод в PDF по ГОСТ 2.106 (формы 1 и 1а, основные надписи 2 и 2а).

Статус: в разработке. Подробные требования — в [docs/REQUIREMENTS.md](docs/REQUIREMENTS.md).

## Требования

- Autodesk Inventor 2025
- .NET 8 SDK
- Visual Studio 2022

## Сборка и установка

1. Откройте `InventorGostSpec.sln` в Visual Studio 2022.
2. Закройте Inventor и соберите решение в конфигурации **Debug**. Аддин автоматически копируется в
   `%APPDATA%\Autodesk\ApplicationPlugins\InventorGostSpec\`.
3. Запустите Inventor. В сборке на вкладке **«Сборка»** появится панель **«Спецификация ГОСТ»**: большие кнопки «Спецификация» и «Позиции в BOM», маленькие — «Раздел», «Авторазделы», «Имя из файла». В детали — кнопка «Раздел» на вкладке **«Управление»**.

Если Inventor установлен не в `C:\Program Files\Autodesk\Inventor 2025\`, укажите путь:
`dotnet build -p:InventorInstallDir="D:\Autodesk\Inventor 2025\"`.
Для Release скопируйте содержимое `src\InventorGostSpec.AddIn\bin\Release\net8.0-windows\` в папку плагинов вручную.
Утилита PDF собирается вместе с аддином и лежит в его папке `PdfTool\`.

Тесты запускаются без Inventor:
`dotnet test tests/InventorGostSpec.Core.Tests`, `dotnet test tests/InventorGostSpec.UI.Tests`,
`dotnet test tests/InventorGostSpec.Excel.Tests`, `dotnet test tests/InventorGostSpec.Pdf.Tests`.

## Команды

| Кнопка | Что делает |
|---|---|
| Раздел | Назначает раздел и поля сортировки выбранным компонентам (или открытой детали). При выборе нескольких компонентов меняются только изменённые поля. |
| Авторазделы | Перед запуском — предупреждение: сколько компонентов затронуто; «Выполнить» доступна только с отмеченной галочкой «Понимаю, что свойства будут записаны в файлы компонентов». Компонентам первого уровня без раздела: Content Center → «Стандартные изделия» (и поля сортировки из наименования), сборки → «Сборочные единицы», детали → «Детали», виртуальные → «Прочие изделия». Деталям без формата — формат из чертежа (поиск — как у «Форматов»), без чертежа — «БЧ» или ничего (настройка «Деталь без чертежа»). Компоненты с заданным разделом пропускаются. |
| Имя из файла | Записывает в наименование (Description) стандартных изделий сборки, включая подсборки, имя их файла — как есть, без перестановок. Перед записью — окно «Было / Станет» с предупреждением: можно выбрать изделия и поправить значение вручную. Если наименование уже совпадает с именем файла, строка помечается и пропускается. Галочка «Очистить поля сортировки» (включена по умолчанию) удаляет у переименованных изделий `SPEC_SortName`, `SPEC_StandardNumber`, `SPEC_Parameters`, заполненные по старому наименованию. Со спецификацией не связана. |
| Спецификация | Открывает окно спецификации. При первом открытии спецификация формируется по составу сборки. |
| Позиции в BOM | Записывает номера позиций из сохранённой спецификации в Item Number спецификации Inventor. |

### Окно спецификации

Окно работает с копией спецификации: в сборку она записывается кнопкой «Сохранить» (Ctrl+S), после чего
нужно сохранить и саму сборку. Состав из сборки перечитывается только кнопкой «Обновить из сборки».

Команды сгруппированы на панели: **Правка** (отменить, вернуть), **Сборка** (обновить, следующее изменение, принять), **Строки** (изделие, текст,
удалить, вверх/вниз), **Структура** (раздел, группа), **Позиции** (по ГОСТ, перенумеровать, резерв),
**Вывод** (проверка, Excel, настройки PDF, PDF, позиции в BOM). Справа — поиск по обозначению, наименованию, примечанию и позиции.

| Клавиши | Действие |
|---|---|
| F5 | Обновить из сборки |
| F3 | Следующее изменение |
| Alt+Enter | Свойства компонента |
| Ctrl+S | Сохранить |
| Ctrl+Z / Ctrl+Y (Ctrl+Shift+Z) | Отменить / вернуть |
| F7 | Проверка спецификации |
| Ctrl+F / Esc | Поиск / очистить поиск |
| Insert | Добавить изделие |
| Ctrl+T | Добавить текст |
| Delete | Удалить строку |
| Ctrl+↑ / Ctrl+↓ | Переместить строку |
| F2, двойной щелчок | Редактировать ячейку |
| Ctrl+щелчок / Shift+щелчок | Выбрать несколько строк |

Размер и положение окна запоминаются.

**Форматы чертежей деталей** (кнопка «Форматы» в группе «Сборка»): для деталей (раздел «Детали») — выбранных строк
или всех, если выбрано не больше одной строки, — ищется чертёж по тем же правилам, что и сборочный (см. ниже), и
читаются форматы **всех** его листов. Результат записывается в `SPEC_Format` детали (файл детали изменится — сохраните
сборку): несколько форматов через запятую в порядке уменьшения — по основному формату от большего к меньшему,
дополнительный раньше основного: «А1, А2х3, А2, А3». В конце — отчёт: что записано, у каких деталей чертёж не найден
— им записывается «БЧ», если формат не был задан раньше (заданный вручную формат не затирается и попадает в отчёт).
Настройка «Деталь без чертежа» рядом с кнопкой «Форматы» (общая, по умолчанию «БЧ»): «БЧ» или «пусто» — графа
«Формат» у деталей без чертежа не заполняется (прежний «БЧ» убирается), и проверка не считает это замечанием.
Действует только для деталей.

**Отмена.** Любое изменение спецификации в окне можно отменить (Ctrl+Z, до 100 шагов) и вернуть (Ctrl+Y):
правку ячеек, перенос и удаление строк, «По ГОСТ», перенумерацию, группы, резерв, обновление из сборки.
Не откатываются свойства, уже записанные в файлы деталей командой «Свойства», и общие настройки (общий справочник
разделов, резерв по умолчанию). Если отменить всё до сохранённого состояния, окно снова считается сохранённым.

**Проверка** (кнопка «Проверка», F7) — список замечаний перед выпуском; двойной щелчок переходит к строке:

| Уровень | Что проверяется |
|---|---|
| Ошибка | нет номера позиции; позиция повторяется; нет наименования |
| Предупреждение | позиции не по порядку записи; нет обозначения (документация, комплексы, сборочные единицы, детали, комплекты); нет формата (для детали без чертежа — «БЧ»); нет количества; обозначение повторяется; позиция отличается от BOM Inventor; компонента нет в сборке; группа без заголовка; нет обозначения или наименования в основной надписи |
| Замечание | изменения из сборки не приняты; раздел компонента не задан в iProperties (определён автоматически); не заполнены «Разраб.», «Пров.» |

Перед созданием PDF ошибки показываются сами, PDF можно создать и с ними.

- Таблица с колонками ГОСТ: Формат, Зона, Поз., Обозначение, Наименование, Кол., Примечание (и единица измерения).
  Заголовки разделов — в графе «Наименование», по центру, подчёркнуты.
- Несколько строк выбираются Ctrl+щелчок (по одной) и Shift+щелчок (диапазоном). «Перенести в раздел»,
  «Перенести в группу», «Свойства компонента…», «Удалить строку» и «Вернуть значение из компонента» применяются
  ко всем выбранным строкам; порядок строк сохраняется, выбор — тоже.
- Группа сортировки (колонка «Гр.», контекстное меню «Группа сортировки») — число 0, 1, 2…, по умолчанию у всех
  строк 0: внутри раздела строки с меньшим числом идут выше, внутри группы — порядок по ГОСТ. Хранится только
  в этой спецификации, в компоненты не записывается. Применяется кнопкой «По ГОСТ».
- «Примечание из детали» (контекстное меню) — вставляет в графу «Примечание» выбранных строк примечание из свойств
  детали: пользовательское свойство «Примечание», а если его нет — «Комментарии» (вкладка «Сводка»). Имя свойства
  задаётся в `%APPDATA%\InventorGostSpec\settings.json` (`notePropertyName`). Уже заполненное примечание заменяется
  только после подтверждения.
- «Свойства компонента…» (контекстное меню, кнопка «Свойства», Alt+Enter) — раздел, формат, единица и поля
  сортировки компонента. Записываются сразу в iProperties файла (действуют во всех сборках), строка тут же
  обновляется: при смене раздела переходит в новый раздел и получает номер из его резерва.
- Любую ячейку можно изменить (двойной щелчок или F2). У строк компонентов это меняет значение только в этой
  спецификации, не в детали; такие ячейки выделены синим курсивом, в подсказке — значение компонента.
  «Вернуть значение из компонента» — в контекстном меню.
- Подсветка после обновления: зелёный фон и метка «новый» — новый компонент, жёлтый и «изменён» — изменился
  (в подсказке «Было: …»), красный и «нет в сборке» — компонента нет в сборке; метка «вручную» — строка добавлена вручную. «Принять изменения» снимает подсветку и удаляет такие строки.
- Порядок строк: перетаскивание за «⋮⋮» или Ctrl+↑/↓ внутри раздела. Номера позиций раздела следуют за порядком.
  «Перенести в раздел» — контекстное меню.
- «+ Изделие» — строка без модели (номер позиции берётся из резерва), «+ Текст» — текстовая строка.
- «Раздел ▾» — меню: вставить раздел, которого нет в части выбранной строки (основной или группе), например
  «Документация» или «Комплекты», либо «Новый раздел…» (свой раздел для этой спецификации или общего справочника).
  Вставленный раздел показывается и без строк — заголовком и резервными строками (если резерва у раздела не было,
  ставится 3); у раздела с позициями под резерв отводятся номера после резерва предыдущего раздела (если свободных нет —
  после «Перенумеровать»), у «Документации» резерв — свободные строки. Строки добавляются в него как обычно
  («Изделие», «Текст» на его заголовке). «Убрать пустой раздел» — в контекстном меню заголовка.
- «Показать файл компонента в папке» и «Показать чертёж в папке» (контекстное меню) — Проводник с выделенным файлом
  детали или сборки (у строки чертежа — самого чертежа) или её чертежа; чертёж ищется так же, как для «Форматов».
- «Разделы по умолчанию» — сбросить разделы компонентов (выбранных строк, если их несколько, иначе всех; из контекстного
  меню — выбранной строки): из файлов удаляется `SPEC_Section`, ручной перенос снимается, раздел определяется по типу.
  Стандартные изделия (раздел «Стандартные изделия» и изделия Content Center) не трогаются.
- «Группа…» — группа «Изделия, устанавливаемые по …» (например, по электромонтажному чертежу МЭ). Записывается после
  основной части со своими разделами (сборочные единицы, детали, стандартные, прочие изделия, материалы), отсортированными
  по ГОСТ; номера позиций продолжаются подряд после основной части. Строки переносятся командой
  «Перенести в группу» в контекстном меню; принадлежность к группе хранится в спецификации сборки, а не в детали.
  Заголовок группы редактируется прямо в таблице; «Удалить группу» возвращает её строки в основную часть.
- «Резерв…» — резерв номеров и округление начала раздела, отдельно для основной части и каждой группы
  (для «Документации» — число свободных строк);
  «Показывать резерв» — пустые строки резервных позиций.
- «Сбросить порядок» — сортировка по ГОСТ и перенумерация; «Перенумеровать» — нумерация в текущем порядке.

### Экспорт в Excel

Кнопка «Excel» (группа «Вывод») выгружает текущее состояние окна в `.xlsx` — для ручной правки и последующего
вывода в PDF по ГОСТ. Пример: [docs/Пример спецификации.xlsx](docs/Пример%20спецификации.xlsx).

- Лист «Спецификация»: колонки ГОСТ (Формат, Зона, Поз., Обозначение, Наименование, Кол., Примечание),
  «Ед. изм.» и «Тип строки» — Группа / Раздел / Изделие / Текст / Резерв / Пустая / Новый лист (выбирается из
  списка). По типу утилита PDF оформляет строки; строки можно свободно править, добавлять и удалять.
  - «Пустая» — пустая строка, добавленная вручную (например, чтобы запись, не помещающаяся на лист, целиком
    перешла на следующий); «Текст» без текста — тоже пустая строка, её можно добавить кнопкой «+ Текст» в окне.
  - «Новый лист» — следующие строки начинаются с нового листа PDF.
  - Колонка «Лист PDF» и жирные линии — разметка листов: номер листа у первой его строки, линия под последней.
    Раскладка та же, что в PDF (с теми же настройками шрифта). После ручной правки разметку обновляет кнопка
    «Разметить листы в Excel» в утилите PDF.
- Лист «Основная надпись»: обозначение (без «СБ»), наименование, организация, литера, подписи — заполняется
  из iProperties сборки, остальное вручную. Должности — как в ГОСТ-шаблонах чертежей Inventor:

  | Основная надпись | iProperties (вкладка «Проект») |
  |---|---|
  | Обозначение | Part Number (без «СБ») |
  | Наименование | Description |
  | Разраб. | Designer (Проектировщик) |
  | Пров. | Checked By (Проверил) |
  | Н. контр. | Engr Approved By (Утвердил, инженер) |
  | Утв. | Mfg Approved By (Утвердил, технолог) |
  | Организация | Company |
  | Перв. примен. | SPEC_FirstUse сборки |
  | литера, шрифт наименования, изменения | в спецификации (окно «Основная надпись») |

  Всё это вводится в окне спецификации кнопкой **«Основная надпись»**: подписи, организация и «Перв. примен.»
  записываются в iProperties сборки; литера, шрифт наименования и изменения (Изм., Кол. уч., Лист, № докум.,
  Подп., Дата) хранятся в спецификации (в файле сборки). Пока в окне ничего не вводили, они, как раньше,
  берутся из прежнего файла Excel.
  «Шрифт наименования, мм» — высота шрифта наименования в основной надписи для этого документа (пусто — из настроек
  утилиты PDF); при повторной выгрузке и при выводе PDF из Inventor берётся из прежнего файла, как и лист «Изменения».
- Лист «Изменения» — графы изменений основной надписи для внесения изменений в КД (ГОСТ 2.503): «Изм.»
  (номер изменения), «Кол. уч.», «Лист», «№ докум.» (обозначение извещения), «Подп.», «Дата». Одна строка — одна
  запись, по порядку внесения; ячейки текстовые («1-3» и «05.25» не превращаются в даты). Заполняется вручную;
  при повторной выгрузке в тот же файл записи переносятся из него (файл должен быть закрыт в Excel).
- Лист «Как заполнять» — памятка. Формат файла описан в `src/InventorGostSpec.Excel/ExcelFormat.cs`.

Резервные строки выгружаются, если включено «Показывать резерв». Изменения в Excel в сборку не возвращаются.

### Исполнения (групповая спецификация, ГОСТ 2.113, вариант А)

- Галочка **«Переменные данные»** (группа «Позиции», рядом с «Показывать резерв») — показать раздел «Переменные данные
  для исполнений:» заранее, без исполнений: основное исполнение под обозначением сборки (пока «Отсутствуют»), в него
  можно переносить строки. Пока есть исполнения, убрать раздел нельзя; без галочки он появляется с первым исполнением.
- Кнопка **«Исполнение»** (группа «Разделы») — выбрать сборку-исполнение (.iam). Исполнения выбирает только
  пользователь. Головная сборка — основное исполнение (обозначение без суффикса), остальные — с «-01», «-02»…
- Состав сравнивается автоматически (при добавлении и при каждом «Обновить из сборки»): составная часть — тот же файл
  (у виртуальных — то же наименование). Есть во всех исполнениях в одинаковом количестве — постоянные данные,
  как сейчас; иначе — «Переменные данные для исполнений:» (в PDF графы «Обозначение» и «Наименование» в этой строке
  объединены) под обозначением своего исполнения, со своими разделами.
- Строки других исполнений серые и только для чтения (данные — из сборки-исполнения). Номер позиции — как у той же
  составной части в постоянных данных, у основного или предыдущего исполнения: тот же файл, то же обозначение или
  другое исполнение того же изделия («АБВГ.10.10.000-01» берёт номер «АБВГ.10.10.000»); новые составные части —
  в конце раздела с новыми номерами. ПКМ на строке исполнения → **«Заменяет поз. …»** — взять номер заменяемой части (как статор
  в примере ГОСТ).
- Строку головной сборки можно вручную перенести между постоянными и переменными данными («Перенести в группу»);
  после этого сравнение её не трогает.
- Исполнение, совпадающее с предыдущим, — заголовок «… (тоже как для …)» без строк; без переменных данных —
  «Отсутствуют»; если переменных данных нет ни у одного — «Различия исполнений … по сборочному чертежу».
- У каждого исполнения свой резерв по разделам (окно «Резерв»), как у групп.
- В сборку-исполнение записывается пометка `SPEC_VersionOf` (и путь к головной — `SPEC_VersionOfFile`, дописывается
  и в старые пометки при «Обновить из сборки» в головной); в её окне спецификации — сообщение, что она исполнение,
  и кнопка **«Номера позиций из головной сборки»**: номера общих компонентов и переменных данных этого исполнения
  из групповой спецификации головной сборки проставляются в спецификацию исполнения и (по запросу) записываются
  в BOM — выноски на чертеже исполнения совпадают с групповой спецификацией. Строки, которых нет в групповой
  спецификации, не меняются (перечисляются в отчёте).
  ПКМ на заголовке исполнения → «Убрать исполнение» (пометка снимается).
- Уровни в окне: **исполнения** («Общие компоненты (постоянные данные)», «Переменные данные для исполнений:»,
  обозначения исполнений — синие заголовки) → **группы «устанавливаемые по …»** → **разделы**. Подпись «Общие
  компоненты» — только в окне (в Excel и PDF постоянные данные идут без заголовка, по ГОСТ).
- Группы «устанавливаемые по …» внутри исполнений: кнопка «Группа» на строке исполнения (основного или любого
  другого) создаёт группу внутри него; строки переносятся «Перенести в группу» — строки головной сборки в общие
  компоненты, основное исполнение и их группы, строки другого исполнения — только в группы своего исполнения; ручной
  перенос сохраняется при обновлении. Кроме того, группы берутся из спецификации самой сборки-исполнения (компонент
  там в группе — и здесь в группе с тем же заголовком; такие группы не переименовываются). Нумерация продолжается по порядку записи. Если исполнения убрать, группы
  основного исполнения становятся группами постоянных данных.

### PDF по ГОСТ

Граница листа А4 рисуется тонкой линией — она видна, когда PDF вставляют в другую программу.

Утилита `InventorGostSpec.PdfTool.exe` строит PDF из файла Excel в формате выше. Это отдельная программа: аддин
связан с ней только форматом файла и командной строкой.

- **Из Inventor** — кнопка «PDF» (группа «Вывод»): текущее состояние окна выгружается во временный Excel, утилита
  строит PDF (по умолчанию «‹обозначение› Спецификация.pdf» в папке сборки). Таблица изменений берётся с листа
  «Изменения» файла «‹обозначение› Спецификация.xlsx» рядом со сборкой, если он есть.
- **Настройки PDF** — кнопка с шестерёнкой рядом с «PDF» в окне спецификации открывает окно утилиты (шрифт, размеры
  шрифтов, сужение текста); если рядом со сборкой есть файл Excel спецификации, он подставляется в окно.
- **Без Inventor** — запустите `PdfTool\InventorGostSpec.PdfTool.exe` из папки аддина (или перетащите на него файл Excel):
  в окне выберите поправленный вручную Excel, файл PDF и шрифт.
- **Командная строка:** `InventorGostSpec.PdfTool.exe файл.xlsx --output файл.pdf [--font "GOST type B"] [--open]`.
  Код возврата 0 — успех, иначе текст ошибки в stderr. `файл.xlsx --mark-sheets` — разметить листы в Excel.

Что выводится:

- первый лист — форма 1 ГОСТ 2.106 (29 строк) с основной надписью по форме 2 ГОСТ 2.104: обозначение, наименование,
  подписи, литера, лист / листов, организация; последующие — форма 1а (32 строки) с надписью 2а;
- графы на поле подшивки (Инв. № подл., Подп. и дата, Взам. инв. №, Инв. № дубл.; на первом листе — Перв. примен.
  и Справ. №), «Копировал» и «Формат А4»;
- заголовки разделов и групп «Изделия, устанавливаемые по …» — по центру графы «Наименование», подчёркнуты (каждая строка), со свободной строкой выше и ниже; заголовок
  не остаётся внизу листа без строк раздела, многострочная запись не разрывается между листами;
- размеры шрифтов (высота прописных букв, ГОСТ 2.304) задаются в окне утилиты PDF, кнопка «По умолчанию»
  возвращает значения как в бланке спецификации КОМПАС-3D:

  | Что | По умолчанию, мм |
  |---|---|
  | Строки таблицы: изделия, заголовки разделов и групп, текст, формат (сжат по ширине графы) | 5 |
  | Заголовки граф «Обозначение», «Наименование», «Примечание» | 5 |
  | Вертикальные заголовки «Формат», «Зона», «Поз.», «Кол.» | 3,5 |
  | Обозначение документа | 7 |
  | Наименование изделия (для документа можно задать своё в Excel — «Шрифт наименования, мм») | 5 |
  | Организация (одной строкой, сжатой по ширине) | 7 |
  | Надписи и данные основной надписи: «Изм.», «Разраб.», фамилии, даты, изменения, литера, листы | 3,5 |
  | Графы на поле подшивки, «Копировал», «Формат А4» | 3,5 |

  Высота берётся по контуру буквы «Н», а не из метрик шрифта (у некоторых шрифтов они неверны); строки текста
  в одной графе — через 1,2 высоты букв;
- допустимое сужение текста (там же, по умолчанию 80 %): текст, который чуть-чуть не помещается в графу, сужается
  по ширине (высота букв не меняется) не больше чем до этой доли; если и так не помещается — переносится по словам
  («ГОСТ 7798-70», «ГОСТ Р ИСО 15973-2005» не разрываются). 100 % — не сужать, сразу переносить; 0 — автоматически
  не переносить вовсе (только по Alt+Enter), сужать сколько нужно;
- ручной перенос: Alt+Enter внутри ячейки Excel — в PDF строка переносится в этом месте (графы «Обозначение»,
  «Наименование», «Примечание», а в основной надписи — наименование);
- пустые строки и разрыв листа задаются в Excel типами «Пустая» и «Новый лист»;
- раздел (Документация, Сборочные единицы…) или группу «Изделия, устанавливаемые по …» можно начать с нового листа:
  ПКМ на заголовке → «Начинать с нового листа» (по умолчанию выключено; в Excel перед заголовком — строка «Новый лист»);
- в окне спецификации границы листов PDF видны синей линией над первой строкой листа и меткой «Лист N»; число листов —
  в строке состояния. Раскладка та же, что у утилиты PDF (шрифт, размеры и сужение — из её настроек);
- над заголовком раздела или группы всегда свободная строка, в том числе в начале листа (поэтому «Документация»
  начинается со второй строки), под заголовком — одна свободная строка;
- промежуток между разделами — одна свободная строка и ещё по пустой строке на каждую резервную позицию (номер
  позиции не печатается); строки «Пустая» из Excel добавляются так же;
- количество — вместе с единицей измерения («2,5 м»);
- формат, который не помещается в графу (ГОСТ 2.106), — дополнительный («А4х3») или несколько («А1, А2»): в графе
  «Формат» «\*)», а в «Примечании» «\*)А4х3» (прежнее примечание — со следующей строки). Одиночный основной формат
  (А1, А3, А4) остаётся в графе. Так же выгружается в Excel, и так же выводится формат, вписанный в Excel вручную;
- изменения: на первом листе — все записи, на остальных — записи, у которых в графе «Лист» указан этот лист,
  и записи без номеров листов (графа «Лист» пустая или «Все» — изменение всего документа, на всех листах)
  («2», «1-3», «1, 4»); в надписи две строки изменений — выводятся две последние записи.

**Шрифт.** По умолчанию — «Gost merged», он поставляется с утилитой (`PdfTool\Fonts\gost_merged.ttf`, исходник —
`src/InventorGostSpec.Pdf/Fonts`). Если файла нет — первый установленный шрифт ГОСТ 2.304 («GOST type B»,
«GOST type A», ISOCPEUR, OpenGost), иначе Arial. Текст всегда наклонный, как в КОМПАС-3D (наклон около 20°, шрифт в файле может быть прямым).
Шрифт, размеры шрифтов и сужение из окна утилиты сохраняются в
`%APPDATA%\InventorGostSpec\pdf.json` и действуют также при выводе PDF и разметке листов из Inventor.
Можно указать путь к файлу `.ttf`.
Подходят только шрифты TrueType (`.ttf`).

Состав берётся из структурированной спецификации Inventor (BOM): справочные компоненты исключаются,
вместо фантомных попадают их дочерние компоненты. Сборочный чертёж автоматически попадает в раздел «Документация»
с кодом «СБ». Чертёж ищется так же, как команда Inventor «Открыть чертёж» (так же — чертежи деталей для «Форматов»
и «Авторазделов»): по всей рабочей папке активного проекта Inventor (`.ipj`) со вложенными папками и по папке модели,
папки `OldVersions` пропускаются:
1. по имени файла (`.idw`/`.dwg`): такое же, как у модели (`Привод.iam` → `Привод.idw`); по обозначению
   (`АБВГ.301234.001.idw`, `…001СБ.idw`, `…001 СБ.idw`); начинается с обозначения (`АБВГ.301234.001СБ Привод.idw`;
   исполнения `…-01` не подходят) или с имени модели и кода «СБ». При равенстве — чертёж в папке модели;
2. если по имени не нашлось — по содержимому: чертежи проекта открываются невидимо и проверяется, какие модели в них.
   Детали подходит только чертёж с ней одной (не сборочный чертёж с листом детали), сборке — и сборочный чертёж
   с листами деталей. Результат запоминается до закрытия Inventor, поэтому медленно только в первый раз; ход поиска —
   в строке состояния Inventor.

Где искался чертёж и что найдено, записывается в журнал `%APPDATA%\InventorGostSpec\log.txt`.

Если чертёж не нашёлся, «Проверка» об этом предупредит; раздел можно вставить вручную («Раздел ▾» → «Документация»)
и добавить в него строку чертежа («Изделие»).

Сторонние документы (не из Inventor: PDF, Word…) добавляются по ПКМ на строке или заголовке «Документации» —
«Добавить сторонний документ…» (можно выбрать несколько файлов). Имя файла — «Обозначение-Наименование-Прочее»
(исполнение «-01» остаётся в обозначении; разделитель может быть и « - »). Наименование — тип документа по коду
в обозначении (ТУ — «Технические условия»), без кода — из имени файла; формат вписывается вручную.
Если файл стороннего документа изменился, строка отмечается «файл изменён» (в строке хранится хэш файла; проверка — при
открытии окна и при обновлении из сборки). Это только уведомление: ссылка на файл не меняется. Кнопка «Сбросить
уведомления» снимает все отметки («новый», «изменён», «файл изменён») и запоминает текущее содержимое файлов.
Путь хранится относительно папки сборки. У строк «Документации» (чертежей и сторонних документов) в меню один пункт — «Показать документ в папке».

Журнал ошибок: `%APPDATA%\InventorGostSpec\log.txt`.

## iProperties компонентов

Обозначение и наименование берутся из стандартных `Part Number` и `Description`. У сборок код «СБ» в конце обозначения
(«АБВГ.301234.001СБ», нужен для сборочных чертежей) в спецификацию не переносится — файлы при этом не меняются.
У сборочных единиц и комплексов в графе «Формат» «А4» — формат их спецификации, но только если у сборки найден
сборочный чертёж (поиск — как у «Открыть чертёж»). Чертежа нет — графа пустая: спецификация без сборочного чертежа
не выпускается. `SPEC_Format` сборки — формат
её сборочного чертежа: он ставится в строку сборочного чертежа в «Документации» её собственной спецификации (если не
задан — читаются форматы листов чертежа). Раздел «Документация» в `SPEC_Section` модели (детали, сборки) не
учитывается: в «Документацию» попадают только найденные чертежи и строки, добавленные вручную. Дополнительно
используются пользовательские свойства:

| Свойство | Значение |
|---|---|
| `SPEC_Section` | Раздел: `Documentation`, `Complexes`, `AssemblyUnits`, `Parts`, `StandardProducts`, `OtherProducts`, `Materials`, `Kits` или id пользовательского раздела |
| `SPEC_Format` | Формат |
| `SPEC_Unit` | Единица измерения |
| `SPEC_FirstUse` | Первичная применяемость («Перв. примен.»): в окне «Раздел»; у сборки идёт в «Перв. примен.» её спецификации. На чертеже графу можно связать с этим свойством модели |
| `SPEC_Group` | Однородная группа (стандартные и прочие изделия) |
| `SPEC_SortName` | Наименование изделия для сортировки («Болт») |
| `SPEC_StandardNumber` | Обозначение стандарта («ГОСТ 7798-70») |
| `SPEC_Parameters` | Основные параметры («М12х60») |
| `SPEC_MaterialKind` | Вид материала: `FerrousMetals`, `MagneticMetals`, `NonFerrousMetals`, `CablesWires`, `Plastics`, `PaperTextile`, `Wood`, `RubberLeather`, `MineralCeramicGlass`, `PaintsChemicals`, `Other` |

Если `SPEC_SortName`, `SPEC_StandardNumber`, `SPEC_Parameters` не заполнены, они берутся из разбора наименования («Болт М12х60 ГОСТ 7798-70»).
