# Требования к InventorGostSpec

Аддин для Autodesk Inventor 2025, формирующий спецификацию по ГОСТ 2.106-2019.

## 1. Общее

- Платформа: C#, .NET 8, Autodesk Inventor 2025, интерфейс WPF.
- Использование локальное, без Vault и командной работы.
- Спецификация строится **только по первому уровню** сборки (подсборки — строки раздела «Сборочные единицы»).
- Исполнения (групповые спецификации) **не поддерживаются** и не должны быть доступны.
- Вывод — окно внутри Inventor, Excel для ручной правки и PDF по ГОСТ (отдельная утилита).

## 2. Данные: два слоя

Деталь может входить в несколько сборок, поэтому данные разделены.

| Свойства компонента (iProperties файла, одинаковы во всех сборках) | Свойства вхождения в сборку (хранятся в спецификации сборки) |
|---|---|
| Раздел (категория) | Поз. |
| Обозначение — стандартное `Part Number` | Зона |
| Наименование — стандартное `Description` | Примечание |
| Формат | Ручной порядок строк |
| Поля стандарта для сортировки (вид, номер, параметры) | Ручное количество и единица измерения |
| | Ручные разделы и строки |
| | Ручные переопределения любых ячеек |

- Пользовательские iProperties называются на английском (префикс `SPEC_`, например `SPEC_Section`, `SPEC_Format`).
- **Примечания хранятся только в спецификации**, не в детали.
- Любую ячейку можно переопределить вручную только в этой спецификации; значение в детали не меняется. Переопределённая ячейка подсвечивается и сбрасывается к значению из компонента.

## 3. Хранение

- Спецификация сборки хранится **внутри файла `.iam`** (AttributeSet, сериализованный JSON).
- Глобальные настройки (справочник разделов, резервы по умолчанию) — JSON в `%AppData%\InventorGostSpec`.

## 4. Разделы

- Порядок по ГОСТ 2.106: Документация → Комплексы → Сборочные единицы → Детали → Стандартные изделия → Прочие изделия → Материалы → Комплекты.
- Справочник разделов по ГОСТ с возможностью добавления пользовательских.
- В спецификацию можно добавлять разделы и строки-примечания вручную.

## 5. Назначение категорий

- Автоматически по правилам: `.iam` → «Сборочные единицы», `.ipt` → «Детали», Content Center → «Стандартные изделия».
- Для компонентов из библиотеки Content Center iProperties проставляются автоматически по команде, запускаемой из целевой сборки. Если свойство уже есть, компонент пропускается.
- Остальное — вручную утилитой, в том числе для нескольких выбранных компонентов сразу.

## 6. Особые компоненты

- **Virtual** (виртуальные) компоненты — полноценные строки спецификации (строки без геометрии).
- **Phantom** — как в Inventor: сам компонент не попадает в спецификацию, попадают его дочерние элементы.
- **Reference** — исключаются.
- Деталь без чертежа — «Формат» остаётся пустым, его можно ввести вручную.

## 7. Колонки

Формат, Зона, Поз., Обозначение, Наименование, Кол., Примечание — все заполняются из компонентов или вручную.

- «Кол.» — число вхождений (шт.). Количество и единицу измерения можно задать вручную. Длины из BOM (Base Quantity) пока не используются, но место для этого заложено.

## 8. Документация

- Автоматически подставляется только сборочный чертёж (файл чертежа рядом со сборкой).
- Остальные документы вводятся вручную.

## 9. Сортировка

Строго по ГОСТ 2.106-2019:

- сборочные единицы, детали — по обозначению;
- стандартные изделия — по виду стандарта (зарубежные DIN, ISO, EN → ГОСТ и ГОСТ Р вместе, как в КОМПАС-3D → отраслевые → СТО → прочие), затем по наименованию, затем по номеру стандарта, затем по основным параметрам по возрастанию;
- прочие изделия и материалы — по правилам ГОСТ для соответствующих разделов.

## 9а. Группы «устанавливаемые по …»

- Составные части, устанавливаемые по отдельному документу (электромонтажному чертежу МЭ и т. п.), записываются
  после основной части под заголовком группы (например, «Изделия, устанавливаемые по электромонтажному чертежу …»).
- Внутри группы — свои разделы с сортировкой по ГОСТ. Номера позиций продолжаются подряд после основной части.
- Групп может быть несколько. Принадлежность строки к группе хранится в спецификации сборки (не в iProperties).
- Резерв позиций задаётся отдельно для основной части и каждой группы.
- Ограничение: строка компонента целиком относится к одной группе. Если одна и та же деталь стоит и в основной части,
  и по МЭ, количество делится вручную (ручная строка в группе и изменённое количество в основной части).

## 10. Позиции и резерв

- Наша спецификация — **главная**. Отдельная команда записывает номера позиций в BOM Inventor (Item Number), чтобы выноски на чертеже совпадали.
- Резерв номеров позиций между разделами (например, СЕ 1–3, резерв 4–5, детали с 6):
  - глобальная настройка резерва для каждого раздела, включая пользовательские; опция «округлять начало раздела» (10, 20, …);
  - переопределение резерва в конкретной спецификации;
  - новый компонент получает первый свободный номер из резерва своего раздела; уже выданные номера не сдвигаются; если резерв закончился — предупреждение и предложение перенумеровать раздел;
  - пустые резервные строки можно показывать или скрывать (переключатель).

## 11. Обновление

Спецификация **никогда не обновляется автоматически**, только по команде пользователя.

- Ручной порядок, разделы и примечания сохраняются.
- Новые компоненты добавляются в конец своего раздела и подсвечиваются.
- Удалённые компоненты помечаются, а не удаляются молча.
- Изменённые данные компонентов (обозначение, количество и т. д.) обновляются с подсветкой.
- Кнопка **полного сброса**: порядок по ГОСТ и перенумерация с учётом резервов.

## 11а. Вывод: Excel и PDF по ГОСТ

- **Excel** — промежуточный формат для ручной правки (сделано): листы «Спецификация» (с колонкой «Тип строки»),
  «Основная надпись», «Изменения» (графы изменений основной надписи: Изм., Кол. уч., Лист, № докум., Подп., Дата;
  при повторной выгрузке переносятся из заменяемого файла), «Как заполнять». Формат описан в `ExcelFormat` и общий для экспорта и утилиты PDF.
- **Утилита PDF по ГОСТ** (сделана, `InventorGostSpec.PdfTool`) — отдельная программа, часть общего приложения как концепция,
  а не как код внутри аддина. Вход — файл Excel указанного формата, выход — PDF по ГОСТ 2.106 / 2.104.
  - Запуск **вне Inventor**: пользователь указывает Excel-файл (в том числе поправленный вручную).
  - Запуск **из Inventor** (кнопка в окне спецификации): аддин выгружает спецификацию во временный файл Excel
    и вызывает внешнюю утилиту, которая строит PDF.
  - Аддин зависит от утилиты только через формат Excel и запуск процесса.
- Принятые решения:
  - шрифт — «Gost merged», поставляется с утилитой; можно выбрать другой в утилите;
  - текст сжимается по ширине до 80 %, дальше — перенос по словам; резервные строки — пустые, без номеров;
  - формы 1 / 1а ГОСТ 2.106 с основными надписями 2 / 2а ГОСТ 2.104; графы на поле подшивки — пустые,
    кроме «Перв. примен.» (из листа «Основная надпись»);
  - в основной надписи две строки изменений: на первом листе — последние записи документа, на остальных —
    последние записи для этого листа (по графе «Лист»).
- Открытые вопросы: лист регистрации изменений (ГОСТ 2.503), графа 26 (обозначение, повёрнутое на 180°),
  заполнение граф на поле подшивки.

## 12. Структура решения

- `InventorGostSpec.Core` — модель, сортировка, резервы, логика обновления; без зависимости от Inventor.
- `InventorGostSpec.AddIn` — аддин, команды на ленте, iProperties, BOM, хранение в `.iam`.
- `InventorGostSpec.UI` — окна WPF.
- `InventorGostSpec.Excel` — формат файла Excel, экспорт и чтение.
- `InventorGostSpec.Pdf` — разметка листов по ГОСТ и вывод PDF; `InventorGostSpec.PdfTool` — утилита (окно и командная строка).
- `tests/*` — тесты `Core`, моделей окон, Excel и PDF.

## 13. Порядок работ

1. Модель данных и сортировка по ГОСТ с тестами.
2. Утилита назначения iProperties.
3. Окно спецификации на WPF.
4. Запись позиций в BOM Inventor.

## 14. Запланировано (не реализовано)

### 14.1. Переменные данные исполнений (ГОСТ 2.106, групповая спецификация)

- Исполнения выбирает только пользователь, автоматически ничего не определяется и не переносится.
- Специальный раздел «Переменные данные для исполнений»: вставляется вручную (как другие разделы, «Раздел ▾»)
  или включается галочкой в настройках. Компоненты переносятся в него по ПКМ («Перенести в раздел»).
- В спецификацию добавляется ссылка на сборку-исполнение (файл .iam). Её компоненты из того же раздела
  («Переменные данные для исполнений» её спецификации) показываются внутри головной спецификации под исполнением:
  серым цветом, с номерами позиций (нумерация общая), без возможности редактирования.
- Обозначения исполнений: нулевое (базовое) — просто обозначение, например «АБВГ.00.00.000»; остальные — с суффиксом
  «-01», «-02», «-03»…
- У исполнений могут быть свои группы «Изделия, устанавливаемые по …» — со своими разделами внутри, как в основной
  части; при показе исполнения в головной спецификации они переносятся вместе с ним.
- Состав сравнивает программа: после того как пользователь выбрал исполнения, компоненты головной сборки
  и сборок-исполнений сравниваются (по обозначению и количеству) и распределяются автоматически — общие в обычные
  разделы, различающиеся в «Переменные данные для исполнений». Ручной перенос по ПКМ остаётся.
- Общие компоненты (одинаковые во всех исполнениях, с одинаковым количеством) записываются как сейчас — в обычных
  разделах. Компоненты, которые относятся не ко всем исполнениям или у которых количество в исполнениях разное, —
  в разделе «Переменные данные для исполнений» под подзаголовками исполнений (обозначение с суффиксом, например
  «АБВГ.00.00.000-01»; у базового — «АБВГ.00.00.000»).
- Резерв (номеров позиций и свободных строк) задаётся и по исполнениям: у каждого исполнения в «Переменных данных»
  — свой резерв по разделам, как сейчас у основной части и групп «устанавливаемые по …».
- Оформление — ГОСТ 2.113-75, п. 5.5.1, вариант А (пример — приложение 6), формы 1 и 1а ГОСТ 2.106:
  - сначала постоянные данные (общие документы и составные части) — как обычная спецификация;
  - затем общий заголовок «Переменные данные для исполнений» (подчёркнут, по центру «Наименования»);
  - для каждого исполнения — заголовок с его обозначением в графе «Наименование» («АГБВ.685910.321»,
    «АГБВ.685910.321-01»); литера под заголовком исполнения не пишется (решение пользователя); под заголовком —
    обычные разделы («Документация»,
    «Сборочные единицы», «Детали»…) с переменными данными этого исполнения;
  - если исполнение полностью совпадает с предыдущим — только заголовок
    «АГБВ.246525.084-10 (тоже как для АГБВ.246525.084)» или «… (тоже как для 02)», данные не повторяются;
    для подряд идущих — «От АГБВ.246525.084 до АГБВ.246525.084-05»;
  - нет переменных данных у исполнения — под заголовком «Отсутствуют»; нет ни у одного — в конце
    «Различия исполнений АГБВ.246527.104 и АГБВ.246527.104-01 по сборочному чертежу»;
  - документы, общие для всех исполнений, — в постоянных данных, остальные — в переменных (п. 5.1);
  - в групповой спецификации допускаются свободные строки как резерв для постоянных и переменных данных (п. 5.4).
- Нумерация позиций (п. 5.5.1 в, г):
  - переменные данные основного (нулевого) исполнения — по правилам единичной спецификации, номера позиций
    продолжают номера постоянных составных частей;
  - у каждого следующего исполнения составные части записываются в порядке номеров позиций, определившихся
    для основного исполнения, независимо от обозначений: часть, заменяющая часть основного исполнения, получает её
    номер (в примере «Статор» АГБВ.686189.349-08 — поз. 10 у основного, АГБВ.686189.350-03 — тоже поз. 10 у -01;
    «Щит подшипниковый» — поз. 11 и в «Сборочных единицах» основного, и в «Деталях» -01);
  - составные части, которых нет в основном исполнении, — в конце своего раздела, с новыми номерами.
  - Как сопоставлять заменяющие части: предварительно — по наименованию (и разделу), с возможностью поправить
    вручную; уточнить у пользователя.
- В сборку-исполнение при добавлении её в головную спецификацию записывается пометка со ссылкой на головную сборку.
  При открытии её спецификации — сообщение «Это исполнение -01 сборки …»; ограничений на работу нет.
